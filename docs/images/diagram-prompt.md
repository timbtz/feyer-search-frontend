# Search architecture diagram brief

Current artifact: [`search-architecture.svg`](search-architecture.svg), an editable vector with selectable text, semantic stage groups, and an accessible title/description. It supersedes the earlier generated block-chart PNG as the architecture illustration. The old PNG remains unchanged.

Method: authored directly as SVG and visually checked from a browser render. No generated bitmap, external font, copied website asset, or inference about live run history is embedded in the new diagram.

## Exact diagram brief

> Create a readable conceptual search architecture, flowing from top to bottom. Start with one validated baseline. Fan out into independent heuristic research directions undertaken with personal Claude/Codex accounts. Beneath each heuristic, show smaller branching numerical refinements. Terminate invalid or unproductive trials with stop caps; preserve their evidence and retain the best validated revisions. Converge two surviving complementary approaches into a new candidate with two scientific parents. Show smaller refinements again beneath that combination. Stop if the combination or its successor cannot justify further compute; retain the better parent when a combination regresses. Repeat combination/refinement as needed using new candidate nodes, preserving an acyclic scientific lineage. End with repeated full confirmation of the exact integrated revision on one chosen host and one submission SHA.
>
> Make the topology itself carry the explanation: thin curved connections, large research nodes, smaller refinement nodes, explicit stop marks, and a visible two-parent convergence. Avoid a page of filled boxes, invented runtime numbers, model-generated speedup claims, or fictitious actual lineage. Use orange only to mark an illustrative retained path and key stage labels. Label the whole diagram “Conceptual workflow” and “not a run history.”
>
> Add a compact execution footer: one shared GitHub ledger for tasks, one-owner claims, exact source, lineage, and measured evidence; beneath it, three independent participants, each with a personal Claude/Codex account and an AMD evaluator running one serial queue against its own baseline. Explain that GitHub access connects teammates without requiring access to a shared VPS. Mark topology and hosting as subject to change and do not claim that all three hosts are deployed or running.

## Interpretation

A, B, C, A*, and C* are illustrative labels, not actual candidate IDs. Orange is an explanatory path through this example, not a measured winner. Phase timings, correctness verdicts, host identities, and real ancestry belong in recorded evidence and the live graph. Screen results are provisional; promotion requires full validation. A successful source merge is not a scientific improvement. Comparisons stay within one host/cohort, and final confirmation re-evaluates the exact integrated SHA.
